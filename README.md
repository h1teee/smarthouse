# Мой Дом (SmartHouse) — Цифровое решение для управления МКД на платформе MAX

## Назначение решения
Единая платформа внутри мессенджера MAX, объединяющая жителей и Управляющую Компанию (УК). Решение автоматизирует адресные PUSH-рассылки жильцам, позволяет отправлять заявки с фото, а также внедряет ИИ для корректировки текстов рассылок УК и человечного объяснения квитанций ЖКХ жителям. Цель проекта — повышение прозрачности работы УК и снижение нагрузки на диспетчерскую службу.

## Основной пользовательский сценарий
**Сценарий Жителя:**
1. Запуск мини-приложения из чат-бота MAX (бесшовная авторизация).
2. Просмотр новостной ленты дома.
3. Подача заявки в УК с прикреплением фото и отслеживание статуса.
4. Просмотр квитанции за ЖКУ с возможностью запросить ИИ-разбор непонятных начислений.

**Сценарий Модератора УК:**
1. Запуск мини-приложения в роли сотрудника УК.
2. Просмотр аналитики по дому.
3. Выбор конкретного адреса (или нескольких) для адресной рассылки.
4. Создание текста рассылки (с возможностью авто-улучшения через ИИ).
5. Нажатие кнопки "Отправить" — бэкенд вычисляет жильцов дома и делает массовую рассылку PUSH-уведомлений через MAX API.

## Состав и архитектура решения
- **Frontend (Mini App)**: React, TypeScript, Vite. Адаптивный мобильный интерфейс в стилистике MAX (VK Bridge логика).
- **Backend (API)**: Go (net/http, database/sql), сборка на Alpine Linux.
- **База данных**: PostgreSQL / Supabase (хранение пользователей, адресов, заявок, квитанций, новостей).
- **Интеграции**: API платформы MAX (вебхуки, отправка PUSH), LLM ИИ (опционально, через API).

## Запуск проекта
Одной командой для запуска всех локальных компонентов через Docker:
```bash
docker-compose up -d --build
```
*Примечание: Перед запуском убедитесь, что файлы `.env` (в корне) и `frontend/.env` заполнены по образцу `.env.example`.*

## Необходимые параметры окружения
Системе требуется подключение к базе данных PostgreSQL (Supabase), токен бота MAX для отправки PUSH-уведомлений и ключ доступа к ИИ (опционально).

## Переменные окружения
Пример конфигурации находится в файле `.env.example`.
- `DB_URL` — строка подключения к базе данных PostgreSQL.
- `MAX_TOKEN` — токен чат-бота платформы MAX.
- `AI_KEY` — API-ключ для ИИ-функций.
- `USE_MOCK_AI` — флаг (`true`/`false`) для включения заглушек ИИ без реального API.
- `VITE_API_URL` (во `frontend/.env`) — URL бэкенда для взаимодействия фронтенда.

## Используемые порты
- **8080** — Backend API
- **3000** — Frontend (веб-сервер)

## Зависимости
- **Backend**: Go 1.22+, `github.com/lib/pq`
- **Frontend**: Node.js, React 18, Vite, `@vkontakte/vk-bridge`

## Внешние сервисы и интеграции
1. **MAX Platform API2** (`platform-api2.max.ru`): Регистрация вебхука и отправка рассылок `POST /messages`. *В Go-клиенте реализован обход проверки сертификатов Минцифры (`InsecureSkipVerify: true`) для совместимости с Alpine.*
2. **Supabase PostgreSQL**: Облачная реляционная база данных (работает без пулера соединений).
3. **OpenAI / Custom LLM**: Интеграция ИИ для улучшения текста и разбора квитанций.

## Описание работы с данными
- Данные пользователей (роль, `user_id` MAX) сохраняются в таблицу `users`.
- Привязка жителей к адресам и лицевым счетам хранится в `user_addresses`.
- Лента рассылок УК пишется в таблицу `feed_items`, а заявки — в `requests`.
- Бэкенд выполняет реляционные джоины (SQL) для вычисления целевой аудитории при PUSH-рассылке по конкретному дому.

## Порядок работы с тестовыми данными
В рамках MVP кэшбек и баланс реализованы как тестовые данные (хранятся в state фронтенда). Часть адресов (`FALLBACK_ADDRESSES`) инициализируется на случай недоступности БД. 
Для тестирования функционала авторизации, если вы не используете интеграцию с MAX, предусмотрен демо-вход через UI (клик по "демо-входу" на экране авторизации подставит счет `61-0001-0015` и адрес).

## Пошаговый сценарий проверки
1. Сделайте `docker-compose up -d --build`.
2. Откройте `http://localhost:3000` в браузере (или перейдите по ссылке на развернутый на Render фронтенд).
3. На экране авторизации нажмите на текст внизу для демо-входа (роль Житель). 
4. Ознакомьтесь с лентой новостей и нажмите на "Квитанции" -> "ИИ Разбор".
5. Зайдите с ролью "УК Модератор" (переключив экран в коде или по deep link `?screen=ukBroadcast`).
6. В разделе "Рассылка" выберите адрес и отправьте тестовое уведомление. Уведомление уйдет в консоль/MAX.

## Примеры ожидаемого поведения
- При отправке заявки статус меняется на "В обработке".
- При рассылке от УК бэкенд отвечает `200 OK` со статусом `"push_result": "sent_to_users"` или `"sent_to_tester"`. Сообщение должно прийти в мессенджер MAX от имени вашего бота.

## Известные ограничения (MVP)
- Кэшбек и баллы программы лояльности хранятся локально (mock-данные).
- Supabase используется напрямую без PgBouncer (ограничение пула коннектов при высоких нагрузках).
- Если ИИ-анализ медленный, фронтенд использует `USE_MOCK_AI` (mock).
- MAX API использует сертификаты Минцифры РФ, поэтому бэкенд на Alpine игнорирует проверку SSL при `POST`-запросах к `platform-api2.max.ru`.

## Порядок остановки и повторного запуска решения
Остановка:
```bash
docker-compose down
```
Пересборка и повторный запуск (с очисткой кэша):
```bash
docker-compose up -d --build --force-recreate
```
