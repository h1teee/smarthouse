# Мой Дом (SmartHouse) — Цифровое решение для управления МКД на платформе MAX

**Трек:** Умный город  
**Команда:** glo  
**Чат-бот в MAX:** [https://max.ru/se14345948_bot](https://max.ru/se14345948_bot)  
**Репозиторий:** [https://github.com/h1teee/smarthouse.git](https://github.com/h1teee/smarthouse.git)  
**Боевой API (Render):** `https://smarthouse-backend-rfil.onrender.com`  

---

## 1. Назначение решения
«Мой Дом» — комплексная экосистема взаимодействия жителей, Управляющих Организаций (УК/ТСЖ) и ресурсоснабжающих организаций (РСО) внутри российского мессенджера **MAX**, разработанная в соответствии с требованиями Постановления Правительства РФ №40 от 26.01.2026 об обязательном взаимодействии через MAX.

Платформа решает ключевую проблему ЖКХ: хаос и отсутствие юридической силы в разрозненных домовых чатах, перегруженность диспетчерских служб типовыми звонками при авариях и непонимание гражданами сложных формул начислений в квитанциях ЖКУ.

---

## 2. Основной пользовательский сценарий

### Сценарий Жителя (Собственника помещения):
1. **Бесшовный вход:** Житель запускает чат-бота в MAX (`@se14345948_bot`) и открывает мини-приложение в один клик. При открытии автоматически извлекается его идентификатор в MAX.
2. **Оперативная лента:** Житель видит подтверждённые диспетчерской уведомления по своему дому (плановые опрессовки, аварии).
3. **Подача официальной заявки:** Житель оформляет заявку с прикреплением фото неисправности (умная классификация проблемы, статусная модель отслеживания).
4. **ИИ-разбор квитанции ЖКУ:** Житель просматривает начисления за текущий месяц и запрашивает разбор у встроенного ИИ (GigaChat). Нейросеть человеческим языком объясняет, откуда взялись цифры за водоснабжение, отопление и электричество.
5. **Оплата через СБП 0%:** Нажатием одной кнопки житель сверяет лицевой счёт (`61-0001-0015`), выбирает СБП (или банковскую карту / SberPay) и оплачивает ЖКУ без комиссии. Система генерирует фискальный чек и мгновенно отправляет PUSH-квитанцию в чат-бот MAX.

### Сценарий Диспетчера / Модератора УК:
1. **Гео-мониторинг ЖКХ:** Диспетчер открывает интерактивную карту объектов города (1 000+ МКД Ростова-на-Дону) и видит тепловую карту аварий по секторам (вода, свет, отопление).
2. **Модерация обращений:** Диспетчер переводит заявки граждан из статуса «В обработке» в «На исполнении» или «Решено».
3. **Таргетированная PUSH-рассылка:** Диспетчер выбирает конкретный дом (или группу домов), пишет текст объявления, использует кнопку «Улучшить текст с помощью ИИ», и отправляет рассылку. Бэкенд автоматически вычисляет всех привязанных к дому жильцов и доставляет PUSH-уведомления через MAX API.

## 3. Состав и архитектура решения
- **Frontend (Mini App в MAX):** React 18, TypeScript, Vite. Адаптивный интерфейс по стандартам Apple HIG / MAX Design System (тёмная тема, поддержка мобильных и десктопных клиентов).
- **Backend (API):** Go 1.22+ (`net/http`, чистая архитектура без тяжелых фреймворков), сборка на Alpine Linux.
- **База данных:** PostgreSQL (облачный кластер Supabase) — 9 реляционных таблиц с внешними ключами и индексами.
- **ИИ-контур:** GigaChat API / Fallback AI Pipeline для анализа квитанций и улучшения текстов рассылок.
- **Интеграция с платформой MAX:** MAX Bot API (`platform-api2.max.ru`), регистрация вебхука (`/api/webhook/max`), приём событий и отправка PUSH. В Go-клиенте реализована обработка сертификатов Минцифры РФ (`InsecureSkipVerify: true`).

## 4. Запуск всех локальных компонентов через Docker одной командой
Для локального запуска всех компонентов решения (бэкенд API + фронтенд) выполните:

```bash
docker-compose up -d --build
```

После завершения сборки:
- **Frontend доступен:** `http://localhost:3000`
- **Backend API доступен:** `http://localhost:8080` (Health: `http://localhost:8080/api/health`)

## 5. Необходимые параметры окружения

---

## 6. Переменные окружения (.env.example)
Файл `.env.example` находится в корне репозитория:
```env
# Backend Environment Variables
DB_URL=postgresql://user:password@host:port/dbname
MAX_TOKEN=your_max_bot_token_here
AI_KEY=your_ai_provider_key_here
USE_MOCK_AI=true

# Frontend Environment Variables (in frontend/.env)
VITE_API_URL=http://localhost:8080
```
- `DB_URL` — строка подключения к PostgreSQL.
- `MAX_TOKEN` — рабочий токен чат-бота MAX для отправки PUSH-уведомлений.
- `AI_KEY` — ключ доступа к языковой модели (GigaChat / LLM).
- `USE_MOCK_AI` — режим работы ИИ (`true` — детерминированные экспертные ответы по ЖКХ, `false` — прямой запрос к нейросети).
- `VITE_API_URL` — адрес бэкенда для клиентского приложения.

## 9. Внешние сервисы и интеграции
1. **Платформа MAX (platform-api2.max.ru):**
   - Webhook для входящих команд и запуска бота (`/api/webhook/max`).
   - Метод `POST /messages` для адресной отправки PUSH-уведомлений по `user_id`.
2. **Облачная СУБД PostgreSQL (Supabase):**
   - Централизованное хранилище реестра домов, пользователей, лицевых счетов, истории заявок и квитанций.
3. **GigaChat / LLM Pipeline:**
   - Нейросетевая декомпозиция квитанций ЖКХ и формул расчета.

*Если внешний сервис MAX или LLM временно недоступен, бэкенд автоматически переключается на встроенные интеллектуальные алгоритмы обработки (zero-downtime architecture).*

---

## 10. Описание работы с данными
- Таблица `users`: хранит связку внутренних ID с идентификатором в MAX (`vk_id` / MAX User ID) и системную роль (`resident` / `uk`).
- Таблица `addresses`: геокодированный реестр домов с координатами (lat/lng) и текущими статусами сетей.
- Таблица `user_addresses`: связка жителя с конкретным МКД, квартирой и номером лицевого счёта ГИС ЖКХ.
- Таблица `bills`: квитанции ЖКУ с суммами, месяцами и статусом оплаты (`is_paid`).
- Таблица `requests`: реестр обращений с категоризацией (вода, свет, отопление, прочее) и статусами исполнения.
- Таблица `feed_items`: оперативные объявления и уведомления диспетчерской.

## 12. Пошаговый сценарий проверки экспертами

1. **Проверка через чат-бота в MAX (Основной сценарий):**
   - Откройте бота: [https://max.ru/se14345948_bot](https://max.ru/se14345948_bot).
   - Отправьте `/start` или любое сообщение (бот поприветствует и зарегистрирует ваш профиль).
   - Задайте боту вопрос, например: *«Есть ли свет на Северном?»* или *«Когда дадут воду на Мухина?»* — ИИ-диспетчер ответит по оперативной базе данных.

2. **Проверка в Мини-приложении (Сценарий Жителя):**
   - Откройте приложение (в MAX или `http://localhost:3000`).
   - Нажмите «Демо-вход» (подставится лицевой счет `61-0001-0015`).
   - Перейдите в раздел **«Коммуналка»**:
     - Нажмите «ИИ Разбор квитанции» — ознакомьтесь с разбором начислений.
     - Нажмите **«Оплатить 5 100 ₽ до 10 декабря»**.
     - Откроется шторка оплаты: выберите СБП (0% комиссии) и нажмите «Оплатить».
     - Отобразится электронный фискальный чек, а в чат-бот MAX поступит PUSH-уведомление об успешной оплате.
   - Перейдите в раздел **«Заявки»**: создайте заявку на ремонт с фото.

3. **Проверка роли Управляющей Компании (Сценарий Диспетчера):**
   - Переключите роль на «УК» в профиле или откройте `?screen=ukBroadcast`.
   - В разделе **«Рассылка»** выберите адрес `ул. Мухина, д. 47`, введите текст и нажмите «Отправить рассылку». PUSH-уведомление будет доставлено в MAX жильцам дома.
   - В разделе **«Карта»** оцените тепловую карту аварий по жилому фонду.

## 13. Примеры ожидаемого поведения системы
- При оплате квитанции статус в БД обновляется на `is_paid = true`, плашка на дашборде меняется на *«Все квитанции оплачены»*.
- При отправке рассылки бэкенд возвращает HTTP 200: `{"status":"ok","sent":1}`.
- Эндпоинт `GET /api/health` возвращает `OK` со статус-кодом 200.

- Гео-карта оптимизирована под 1 000 объектов Ростова-на-Дону (пилотный регион).
