# Smart Home (Умный Дом MAX)

## Назначение решения
Мини-приложение для платформы MAX, предназначенное для автоматизации взаимодействия между жителями многоквартирных домов и управляющими компаниями. Решает проблему непрозрачности обращений и ускоряет процесс уведомления жителей об авариях.

## Основной пользовательский сценарий
1. Житель фотографирует объявление на подъезде или проблему. ИИ распознает суть и формирует заявку.
2. Модератор УК получает готовую заявку, проверяет (модерирует) и одним кликом запускает PUSH-рассылку по жителям конкретного дома (адреса).

## Состав и архитектура решения
- Фронтенд: React, TypeScript, Vite. Стилизация чистым CSS Modules. Подключение к MAX Bridge для работы внутри мессенджера.
- Решение оформлено в виде единого SPA (Single Page Application), способного принимать параметры (Deep Links).

## Параметры и переменные окружения
На данный момент MVP не требует специфичных переменных окружения (в \`.env\`). 
Используемые порты при запуске \`npm run dev\`: **5173**.

## Зависимости
- React 19, TypeScript, Vite, @vkontakte/vk-bridge. Зафиксированы в \`package.json\`.

## Внешние сервисы и интеграции
- **MAX Bridge:** Инициализируется на старте приложения (событие \`VKWebAppInit\`) для нативной поддержки мессенджера MAX.

## Описание работы с данными
В MVP-версии используются смоделированные тестовые данные, зашитые во фронтенд (в файлах экранов, например \`MOCK_HOUSES\`, \`expenseHistory\`). При интеграции с реальным бэкендом данные будут поступать через защищенное API УК.

## Порядок работы с тестовыми данными
Все необходимые данные (адреса, счета, статусы заявок) уже встроены в проект. Дополнительной загрузки файлов не требуется.

## Пошаговый сценарий проверки
1. Откройте приложение (в идеале с параметром \`?screen=auth\` или просто главную).
2. Выберите роль **"Житель"**.
3. Пройдите авторизацию, укажите адрес.
4. На главном экране нажмите кнопку сканирования объявления (ИИ Камера), сделайте "фото" и отправьте на модерацию.
5. Переключитесь на роль **"УК Модератор"** через верхний переключатель.
6. Перейдите в раздел модерации, проверьте карточку и нажмите "Подтвердить".
7. Проверьте работоспособность шторки "Отклонить", проведя по ней вниз (свайп).

## Примеры ожидаемого поведения системы
- При нажатии на кнопки отправки (например, "Запустить рассылку") интерфейс блокируется и показывает "Отправка..." (имитация сетевого ожидания).
- При свайпе вниз по шторке (BottomSheet) на сенсорных устройствах (или в эмуляторе разработчика) она закрывается.
- Переключение экранов сопровождается плавными iOS-подобными анимациями.

## Известные ограничения
- Backend и реальная генерация PUSH-сообщений через API MAX находятся в разработке. Сейчас интерфейс симулирует успешный ответ.
- Работа с камерой симулируется (используется мок-изображение).
